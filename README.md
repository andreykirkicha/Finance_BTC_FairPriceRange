# Интервалы справедливых цен BTC-опционов

## Структура проекта

| Путь | Что реализовано |
| --- | --- |
| `deribit_data/prepare_quotes.py` | Чтение SQL-дампа, исправление дат, отбор ATM-котировок и сохранение `quotes.csv` |
| `deribit_data/prepare_otc_trades.py` | Отбор OTC-сделок из годовой выгрузки или загрузка через API Deribit |
| `deribit_data/proccess_snapshot.py` | Чтение снимка котировок, передача значений в расчёты, сохранение CSV, статистики и отчёта |
| `option_pricing/inverse_call.py` | Цена обратного call-опциона в BTC и восстановление IV методом Брента |
| `option_pricing/snapshot.py` | Расчёт IV набора котировок, фильтры и причины исключения |
| `option_pricing/__init__.py` | Публичные импорты математических функций и классов |
| `pyproject.toml` | Зависимости, состав пакетов и настройки линтера |
| `datasets/` | Git LFS-указатель на архив исходного дампа и контрольная сумма |
| `data/` | Локальные исходные данные и подготовленные таблицы `quotes.csv`, `otc_trades.csv` |
| `results/` | Результаты расчёта IV: CSV, JSON со статистикой и Markdown-отчёт |

`deribit_data` отвечает за работу с данными. `option_pricing` выполняет расчёты
в памяти и не зависит от файлов, API или `deribit_data`.

## Запуск

Нужен Python 3.10+. Выполнять из корня проекта:

```bash
python3 -m pip install -e .
python3 -m deribit_data.prepare_quotes
python3 -m deribit_data.prepare_otc_trades
python3 -m deribit_data.proccess_snapshot
```

Подготовка использует `data/dump.sql` и годовую OTC-выгрузку
`data/otc_2024/btc_call_block_trades.csv.gz`. Вместо локальной OTC-выгрузки
можно загрузить выбранный период из API:

```bash
python3 -m deribit_data.prepare_otc_trades --download
```

По умолчанию подготовка выбирает 20 мая — 2 июня 2024 года включительно
и экспирацию 26 июля 2024 года. Даты меняются через `--start`, `--end`
(исключительная граница UTC) и `--expiry`.
Расчёт IV обрабатывает один снимок дампа: последний по умолчанию или заданный
через `--snapshot`. Параметры каждой команды доступны через `--help`.

## Исследовательский пайплайн

1. **Сбор исторических биржевых данных.** Формируем группу опционов одной
   экспирации со страйками около цены базисного фьючерса (`K ≈ F`), чтобы опционы
   были ATM. Сейчас используются котировки bid/ask из SQL-дампа, цена — их
   середина (`mid`).
2. **Сбор OTC-сделок.** Готовим сделки за сопоставимый период и по выбранным
   контрактам для последующей проверки модели.
3. **Расчёт IV.** Для выбранной группы опционов численно восстанавливаем сигму
   из уравнения Блэка — Шоулза методом Брента с учётом обратного call и цены в BTC.
4. **Квантили.** По полученным значениям IV определяем нижнюю и верхнюю
   квантильные границы волатильности.
5. **Интервал справедливых цен.** Подставляем обе границы волатильности обратно
   в формулу цены опциона при одинаковых форварде, страйке и сроке до экспирации.
   Получаем нижнюю и верхнюю границы цены.
6. **Тестирование модели.** Проверяем интервалы на отложенных биржевых опционах
   и на OTC-сделках.

Для первой проверки заранее фиксируем группу биржевых опционов, исключённую
из оценки параметров и квантилей. Затем проверяем модель на этих опционах.
Для второй оцениваем, насколько фактические OTC-цены попадают в интервал
и насколько отклоняются от него.
