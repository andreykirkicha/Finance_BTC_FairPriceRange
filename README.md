# Исторические данные BTC call для интервалов справедливых цен

Исследуем BTC inverse call на Deribit за **20 мая — 2 июня 2024 года включительно**,
с экспирацией **26 июля 2024 года, 08:00 UTC**. Рабочие таблицы уже подготовлены.
Для анализа начинайте с `data/quotes.csv` и `data/otc_trades.csv`.

## Структура

| Путь | Назначение |
| --- | --- |
| `data/dump.sql` | Исходный SQL-дамп котировок; хранится без изменений |
| `data/otc_2024/` | Сохранённая годовая OTC-выгрузка: общий CSV, исходные дневные ответы, квитанции и пример |
| `data/quotes.csv` | Котировки выбранного периода, 11 колонок |
| `data/otc_trades.csv` | OTC выбранного периода в исходной годовой схеме, 26 колонок |
| `deribit_data/prepare_quotes.py` | Чтение дампа, исправление дат, фильтры и подготовка котировок |
| `deribit_data/prepare_otc_trades.py` | Отбор OTC из годового файла; при явном запросе — загрузка истории |
| `deribit_data/iv.py` | Формула inverse call и восстановление IV методом Брента |
| `deribit_data/iv_pipeline.py` | Существующий расчёт IV для одного снимка дампа |
| `tests/` | Проверки подготовки данных и расчёта IV |

`datasets/` содержит ссылку Git LFS и контрольную сумму исходного gzip-архива.
В текущем checkout это указатель, а не скачанный архив; команды используют
имеющийся `data/dump.sql`. Каталог `data/` исключён из Git: при переносе проекта
данные нужно копировать отдельно. Единственная документация подготовки — этот README.

## Воспроизведение подготовки

Нужен Python **3.10+**. Подготовка таблиц использует стандартную библиотеку,
для расчёта IV нужен SciPy (в `pyproject.toml` указан `scipy>=1.15`).

Из корня проекта:

```bash
python3 -m deribit_data.prepare_quotes
python3 -m deribit_data.prepare_otc_trades
```

Первая команда последовательно читает COPY-блок `options_table` из дампа.
В памяти остаются только выбранные котировки и служебные индексы;
промежуточная база, кеши и контрольные точки на диске не создаются.
Для повторного запуска нужен новый проход дампа.

Вторая команда работает **без сети**: читает
`data/otc_2024/btc_call_block_trades.csv.gz` и записывает выборку в
`data/otc_trades.csv`. Все файлы годовой выгрузки остаются неизменными.

По умолчанию обе команды используют уже выбранные даты и экспирацию.
Параметры можно указать явно, например:

```bash
python3 -m deribit_data.prepare_quotes \
  --dump data/dump.sql --output data/quotes.csv \
  --start 2024-05-20 --end 2024-06-03 --expiry 2024-07-26
```

`--end` — исключительная граница в UTC. Справка доступна через `--help`.
Команды заменяют итоговый CSV только после успешного завершения;
счётчики отбора выводятся в терминал, отдельные файлы отчётов не создаются.

Если потребуется заново получить OTC из исторического API:

```bash
python3 -m deribit_data.prepare_otc_trades --download
```

Источник — `history.deribit.com/api/v2/public/get_last_trades_by_currency_and_time`.
Загружается только заданный период. При `has_more=true` временной диапазон делится,
пока все ответы не подтвердят полноту. Сохраняются повторы запросов при временных
ошибках и проверки дубликатов. Пакетность определяется до отбора call:
учитываются также put-ноги пакета. Дневные файлы и манифесты не создаются.
Повторная загрузка заменяет только итоговую таблицу выбранного периода.

## Подготовка котировок

1. Из `options_table` выбираются BTC call нужного периода и экспирации.
   ETH, put, другие экспирации и таблица бессрочных фьючерсов не используются.
2. Время наблюдения трактуется как UTC. Годы экспирации `0024/0025`
   исправляются на `2024/2025`, полночь экспирации — на `08:00 UTC`.
   К имени call-контракта добавляется суффикс `-C`, если его нет.
3. Берутся `F = underlying_price`, `K = strike`, исходные bid и ask.
   Цена `mid = (bid + ask) / 2` пересчитывается; mark и готовый mid не подставляются.
4. Оставляются положительные конечные F/K/bid/ask, `bid ≤ ask`,
   `max(1 − K/F, 0) < mid < 1`, `|ln(K/F)| ≤ 0.15`,
   `(ask − bid)/mid ≤ 0.20`.
5. Вычисляются остаточный срок по ACT/365F, денежность и спред.
   Дубликаты пары «время — контракт» считаются ошибкой.
   Результат сортируется по времени и контракту.

| Колонка `quotes.csv` | Содержание |
| --- | --- |
| `timestamp_utc`, `instrument_name` | Время наблюдения UTC и контракт |
| `expiry_utc`, `strike_usd`, `forward_usd` | Экспирация, страйк K и базисная цена F; цены BTC в USD |
| `bid_btc`, `ask_btc`, `mid_btc` | Премии в BTC за единицу базового актива |
| `time_to_expiry_years` | Секунды до экспирации / (365 × 86400) |
| `log_moneyness` | ln(K/F) |
| `relative_spread` | (ask − bid)/mid, доля |

Период зафиксирован после ранее проведённой проверки доступности котировок.
В 336 часовых снимках, выбранных ближайшими к HH:30, были доступны 18–21 контракт,
медиана — 20, медианный часовой спред — 1,98%. Код поиска и сравнения окон удалён.
В рабочей таблице сохранены **все** подходящие снимки, без часового прореживания.

## Подготовка OTC

Из годового CSV выбираются BTC call по тем же UTC-датам, экспирации и объединению
контрактов из `quotes.csv`. Цена сделки и её отклонение от котировок
не участвуют в отборе. Это ретроспективный список контрактов за весь период;
он ещё не задаёт правило обучения и отложенной проверки.

Схема полностью совпадает с `data/otc_2024/sample.csv` и годовым CSV.
При локальном отборе значения всех полей, включая пустые ячейки и `source_file`,
копируются без преобразований. Строки сортируются по `timestamp_ms` и `trade_id`.

```text
trade_id, block_trade_id, trade_seq, timestamp_ms, trade_utc,
instrument_name, currency, option_type, expiry_utc, strike_usd,
price_btc, amount_btc, contracts, direction, index_price_usd,
mark_price_btc, exchange_iv_pct, days_to_expiry, block_trade_leg_count,
observed_option_legs_in_block, package_status, block_rfq_id, combo_id,
combo_trade_id, block_delayed, source_file
```

`price_btc` — фактическая цена сделки. `index_price_usd` — спотовый индекс,
его нельзя автоматически подставлять вместо форварда. Биржевая IV и mark
остаются исходными справочными полями.
`package_status=multiple_legs` обозначает ногу пакета,
`single_leg_reported` — заявленную отдельную сделку, `unknown` — неопределённый статус.
Пути `source_file` локальной выборки относятся к каталогу `data/otc_2024/`;
исходные обратные слеши в этих значениях сохранены.

## IV и проверки

Математическая реализация IV сохранена: собственная IV восстанавливается
по mid методом Брента, `r = 0`; биржевая IV используется только для диагностики.
`iv_pipeline.py` по-прежнему обрабатывает один снимок дампа,
по умолчанию последний, и при запуске создаёт свои результаты в `results/`.
Пробные результаты за 4 июня удалены. Расчёт временных кривых интервалов —
следующий этап; в двух подготовленных CSV IV и границ интервалов ещё нет.

```bash
python3 -m unittest discover -s tests -v
```

Тесты работают без сети и проверяют даты, единицы, фильтры, исходную OTC-схему,
сохранность значений, полноту загрузки, дубликаты и работу IV-конвейера.

Ограничения данных: в дампе нет времени обновления и размеров отдельных bid/ask;
свежесть и глубину заявок подтвердить нельзя. Зарегистрированные block trades
представляют только часть OTC-рынка, а цены ног пакета требуют отдельной интерпретации.
В каждом снимке около 20 контрактов; множество строк во времени не превращает
их в большую независимую выборку для хвостовых квантилей.
